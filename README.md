# Telegraph Messenger

Десктопний месенджер на Python із графічним інтерфейсом Tkinter та WebSocket-сервером. Повідомлення шифруються на клієнті: сервер зберігає лише зашифрований текст, публічні ключі та хеші облікових даних.

## Можливості

- реєстрація та вхід з іменем користувача (`a-z`, `0-9`, `_`, від 3 до 20 символів);
- пароль під час реєстрації — щонайменше 16 символів; на сервері зберігається його salted scrypt-хеш;
- наскрізне шифрування повідомлень за допомогою PyNaCl; приватний ключ не надсилається на сервер;
- доставка повідомлень онлайн і черга для користувача, який був офлайн;
- одне підключення може працювати на кількох пристроях користувача;
- сховище на вибір: локальний файл JSON або MongoDB / MongoDB Atlas;
- автоматичне створення віртуального середовища та встановлення залежностей через стартовий скрипт.

## Структура

- `backend/server.py` — WebSocket-сервер, авторизація, доставка та зберігання шифротексту.
- `frontend/Connection/` — WebSocket-клієнт, реєстрація, вхід і криптографія.
- `frontend/interface/` — вікна Tkinter для входу, реєстрації та листування.
- `main.py` — основний запускатор: готує `.venv`, встановлює залежності та запускає компоненти.
- `.env.example` — безпечний шаблон конфігурації.

## Вимоги

- Python 3.9+ з `venv`, `pip` і Tkinter;
- інтернет лише для першого встановлення бібліотек або для MongoDB Atlas;
- для Linux може знадобитися системний пакет `python3-tk`.

## Швидкий локальний запуск

1. Скопіюйте шаблон конфігурації:

   ```powershell
   Copy-Item .env.example .env
   ```

   У macOS/Linux: `cp .env.example .env`.

2. На Windows двічі клацніть [`start.bat`](start.bat) або виконайте:

   ```powershell
   py -3 main.py
   ```

   В macOS/Linux:

   ```sh
   python3 main.py
   ```

   Скрипт створить `.venv`, встановить залежності, підніме сервер і відкриє клієнт. Після закриття клієнта сервер, запущений цим способом, також зупиниться.

Корисні варіанти:

```sh
python3 main.py backend        # лише сервер
python3 main.py frontend       # лише клієнт
python3 main.py --install-only # лише залежності
```

Після інсталяції також доступні прямі команди: `python -m backend.server` і `python -m frontend.main`.

## Конфігурація `.env`

Файл `.env` читають і сервер, і клієнт. Він уже виключений з Git, тому не додавайте до репозиторію реальні URI, паролі або дані доступу.

### Локальний запуск на одному комп’ютері

```dotenv
# Сервер доступний лише з цього комп’ютера.
HOST=localhost
PORT=8765

# Адреса, до якої підключається локальний клієнт.
MESSENGER_SERVER_URL=ws://localhost:8765

# Порожнє значення вмикає локальне JSON-сховище.
MONGO_URI=
DATA_FILE=server_data.json
```

### `.env` на хості сервера

Якщо до сервера підключатимуться інші пристрої, розмістіть на сервері окремий `.env`:

```dotenv
# Прослуховувати всі мережеві інтерфейси сервера.
HOST=0.0.0.0
PORT=8765

# Значення використовується, якщо на цьому ж хості запускають GUI-клієнт.
MESSENGER_SERVER_URL=ws://127.0.0.1:8765

# Варіант 1: локальне сховище (подбайте про резервні копії та права доступу).
MONGO_URI=
DATA_FILE=server_data.json

# Варіант 2: MongoDB — розкоментуйте та заповніть URI замість локального сховища.
# MONGO_URI=mongodb+srv://<user>:<password>@<cluster>/<database>?retryWrites=true&w=majority
# MONGO_DB=Messenger
# MONGO_COLLECTION_USERS=users_login
# MONGO_COLLECTION_MESSAGES=messages
```

Відкрийте у фаєрволі лише `PORT` для потрібних IP-адрес або приватної мережі. Поточний сервер не налаштовує TLS самостійно: для доступу через інтернет використовуйте TLS-термінатор / reverse proxy з `wss://` або VPN. Не публікуйте звичайний `ws://` у відкритому інтернеті.

### `.env` у користувача (віддалений клієнт)

Користувачеві не потрібні `HOST`, `PORT`, `MONGO_URI` чи дані MongoDB. Достатньо вказати адресу сервера:

```dotenv
# Якщо сервер доступний тільки у домашній/корпоративній мережі.
MESSENGER_SERVER_URL=ws://192.168.1.50:8765

# Для сервера за TLS reverse proxy використовуйте домен і WSS:
# MESSENGER_SERVER_URL=wss://messenger.example.com
```

Якщо файли сервера й клієнта лежать в одній спільній директорії, вони використовують той самий `.env`. Для реального розгортання тримайте їх в окремих директоріях або запускайте клієнт із власною `.env`, де задано лише `MESSENGER_SERVER_URL`.

## MongoDB Atlas

Щоб увімкнути MongoDB, задайте `MONGO_URI`. За відсутності або недоступності URI сервер переходить на `DATA_FILE`. Для Atlas:

- додайте публічну IP-адресу сервера в **Network Access**;
- скопіюйте URI з **Connect → Drivers**;
- percent-encode спеціальні символи у паролі;
- не публікуйте URI та не зберігайте його у Git.

Для `mongodb+srv://` проєкт використовує актуальний CA bundle для TLS-з’єднання.

## Дані та обмеження безпеки

- Локальний `server_data.json` містить облікові записи (із хешами) та шифротексти; створюйте резервні копії й обмежте доступ до файлу.
- Сервер не має приватних ключів і не бачить відкритого тексту повідомлень.
- Доставка позначається виконаною після успішного надсилання клієнту; застосунок не реалізує підтвердження прочитання.
- Втрата приватного ключа на пристрої означає, що старі повідомлення на ньому неможливо розшифрувати.
